# ExamPaper

Generates original, exam-style GCSE Higher Mathematics practice papers (Edexcel specification) with mark schemes, exported as print-ready PDFs.

## How it works

ExamPaper uses a **generate-verify pipeline**:

1. **Blueprint.** A paper blueprint (`backend/app/blueprints/edexcel_higher.json`) encodes the structure of real papers: topic weightings, mark distributions and question-type patterns, derived from analysis of the June 2022 and June 2023 Higher papers.
2. **Generate.** Deterministic Python builds the questions. Each archetype in `backend/app/generators/` is a builder that draws its parameters — coefficients, lengths, names, scenarios — from a seeded `random.Random`, so the same seed always gives the same paper. Nothing is generated by a model.
3. **Verify.** The builder derives the answer with **SymPy** rather than hard-coding it, and checks the candidate against the identity the question claims (an expansion re-expanded, a factorisation multiplied back out, a simultaneous pair re-solved). A set of parameters that fails the check is discarded and another is drawn, so a question only ever ships with an answer SymPy agrees with.
4. **Assemble.** Questions are assembled to match real paper proportions (~21 questions averaging ~3.8 marks), with a separate mark scheme.
5. **Render.** React components lay out the paper, diagrams are generated as SVG from the same parameters as the question, and **Playwright** renders the result to PDF.

## Tech stack

| Layer | Tools |
|---|---|
| Backend | Python, FastAPI, SymPy |
| Database | Postgres (SQLAlchemy + Alembic) |
| Accounts & payments | Clerk (auth), Stripe (payments) |
| Frontend | React, TypeScript, Vite, Tailwind CSS v4, React Router |
| PDF output | Playwright / Chromium |
| Hosting | Railway + Neon |

## Running locally

Requires Python 3.14, Node.js 22, and a Postgres database.

Copy `backend/.env.example` to `backend/.env` and `frontend/.env.example` to
`frontend/.env`, then fill both in (Clerk and Stripe keys, `DATABASE_URL`).

**Backend** (port 8000), from the repo root:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
python -m playwright install chromium
cd backend
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

`alembic upgrade head` is needed once before the first run, and again after any
migration is added.

**Frontend** (port 5173, proxies `/api` to the backend):

```bash
cd frontend
npm install
npm run dev
```

Then open http://localhost:5173, pick topics, and generate a paper.

## Tests

`backend/tests/` covers answer verification, paper assembly, diagram
generation, paper structure, auth, generation limits, render caps and the
billing webhooks. The suite runs on the standard library's `unittest`; pytest
just gives nicer output and discovery. From `backend/`:

```bash
python -m venv .venv-dev && . .venv-dev/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
pytest tests -q
```
